## 이번에 반영한 최초 동의 흐름

- 이메일 가입 전 동의. 이미 가입한 계정은 로그인 후 DB의 동의 버전·시각 확인.
- 동의 기록이 없거나 실질적인 처리 변경으로 새 동의가 필요한 계정만 안내. 일반 앱 업데이트마다 새 버전을 만들지 않음.
- 같은 버전에 동의한 계정은 이메일·카카오·구글 재로그인 및 자동 로그인에서 반복 동의를 요구하지 않음.
- 신규 소셜 계정은 제공자 인증 후 앱 동의를 받기 전 DB에 등록하지 않음. 임시 식별자·이름은 메모리에서 최대 5분 후 폐기.
- 현재 동의 없는 계정의 새로운 저장/프로필 수정은 서버에서도 차단. 기존 정보 조회·삭제, 게스트 추천은 유지.
- 여행 조건·코스 저장은 별도 선택이며 이력 자동 저장은 하지 않음.
- `consentVersion`과 `consentedAt`은 현재 동의 기록. 모든 과거 버전의 감사 이력을 별도로 쌓는 설계는 아님.
- 정책 전문·외부 사업자 계약/국외 처리/아동 이용 정책의 법적 검토 완료를 뜻하지 않음.

## 비용의 경계

개발 도구, 로컬 Android 빌드·서명, 자동 테스트, 문서·스토어 이미지 제작은 유료 서비스 추가 없이 진행할 수 있습니다.
Google Play 개발자 등록비 **미화 25달러(1회)**는 실제 Google Play 출시 시 별도 필요합니다. 계정 결제·본인 인증·약관 동의는 사용자가 진행해야 합니다. [공식 등록 안내](https://support.google.com/googleplay/android-developer/answer/6112435?hl=ko)

API/DB의 무료 요금제는 소규모 베타 후보이지 상시 운영 보장과 동의어가 아닙니다.
예를 들어 Render 무료 API 서버는 15분 유휴 후 중지하고 재시작에 약 1분 걸릴 수 있으며, 무료 Postgres는 생성 30일 후 만료됩니다. 결제수단을 등록한 계정은 일부 사용량 초과 과금도 있으므로 무료 인스턴스 선택만으로 예산 통제가 끝나지 않습니다. [Render 무료 제한](https://render.com/docs/free)
Supabase 무료 DB도 용량/트래픽 제한 및 1주 비활성 시 일시정지 조건이 있습니다. [Supabase 요금제](https://supabase.com/pricing)

따라서 다음 중 하나를 명시적으로 선택해야 합니다.

1. **외부 서비스비 0원 소규모 베타:** 무료 호스팅 한도 안에서 API/DB 운영, 중지·쿼터 오류 UI 제공, AI 없이도 핵심 추천 제공. 고정 무료 HTTPS 서브도메인을 쓰면 도메인 구매는 필수가 아님. 실제 계정·지역·데이터 이전 조건 확인 후 배포.
2. **기존 PC 자체 운영:** 서버 임대료는 없으나 전기·인터넷 비용과 PC 상시 가동·장애 대응이 필요. 현재 임시 개발 터널과 접속 암호를 그대로 정식 서비스로 공개하지 않음.
3. **안정적 상시 운영:** 무료 자원 제공 기관/학교의 승인된 서버가 있으면 검토. 그렇지 않으면 서버 예산 또는 서비스 가용성 수준 조정 필요.

요금제 자동 업그레이드·유료 AI·GPU 서버·도메인 구매를 임의로 신청하지 않았습니다. 운영 데이터를 무료 업체에 옮기는 작업도 아직 하지 않았습니다.

현재 미해결: 32시간 다일 추천에서 조건 충족 후보 0, 실제 소셜 로그인 미검증, 사진별 권리 일부 미확정, 상시 운영 인프라 없음. 기존 디버그 APK의 공개 배포/릴리스 빌드 차단을 유지합니다.

## Ollama를 바꿀지 판단하는 방법

Ollama는 실행 프로그램, Qwen은 모델, CUDA는 GPU 실행 환경입니다. 세 가지를 구분해야 합니다.
현재 설치 확인: Ollama 0.34.0 / qwen3:8b(약 5.23GB 모델 파일) / GTX 1660 SUPER 6GB / NVIDIA 드라이버 610.74.
이번 확인 시 전체 GPU 메모리 사용 약 4,947MiB. 이것만으로 메모리 부족이 오류 원인이라고 확정하지 않습니다.
직전 실제 앱 검사에서는 CUDA 초기화 실패로 기본 설명을 반환한 호출(약 18.5초)과 Ollama 설명에 성공한 재시도(약 29.6초)가 모두 있었습니다.

### 권장 순서

1. **모델 비교:** qwen3:4b Q4_K_M(공식 파일 약 2.5GB)을 첫 후보로 삼습니다. 기존 8B를 지우지 않고 비교하며, 작은 모델이라고 한국어 품질/안정성이 보장되지는 않습니다. [공식 모델·Apache2.0 라이선스](https://ollama.com/library/qwen3:4b)
2. **자원/설정:** 추론 끄기(현재 `think:false`), 요청 동시 실행 1개, 컨텍스트/출력 길이 제한, 로딩 시간과 생성 시간 분리 측정. 현재 앱의 Ollama 옵션과 실제 설치 버전 지원 여부를 확인한 뒤 적용.
3. **CUDA 오류가 재현되면:** GPU/CPU 실행을 분리해 원인 진단. CPU가 안정적이어도 휴대폰 응답 대기 시간과 서버 동시 요청을 통과하는지 확인. 드라이버 삭제·다운그레이드·전역 환경변수 변경을 자동 수행하지 않음. [공식 문제 해결](https://docs.ollama.com/troubleshooting)
4. **실행기 문제로 좁혀지면:** `llama.cpp`의 CPU/Vulkan 등 다른 실행 경로를 후보로 비교. 같은 CUDA 환경을 그대로 쓰면 프로그램 이름만 바꿔도 같은 문제가 남을 수 있습니다. API 어댑터·중단/시간 제한·라이선스·패키징을 별도 검증. [공식 llama.cpp](https://github.com/ggml-org/llama.cpp)
5. **무료 운영에 AI 서버가 없으면:** 기본 버튼 추천·서버 규칙 설명을 운영 기능으로 유지하고 자연어 AI는 가용할 때만 보조 제공. AI 호출 실패 시 대체 설명임을 표시하고 실패 연속 시 잠시 호출 중지하는 보호장치 추가. 공개 운영을 개인 PC의 AI 응답에 필수 의존시키지 않음.

### 비교 평가 기준 (목표이며 아직 달성 결과가 아님)

- 동일한 가상 한국어 여행 조건 30개 이상: 도시·정류장/터미널·기간·식사·걷기 제한 보존, 입력에 없는 조건 생성 여부 검사.
- 동일 코스 설명 20개 이상: 장소/수치/근거 일치, 실제 교통 정보와 추정치 혼동 여부, 확인되지 않은 요금·영업시간 생성 여부.
- 최초/반복 실행과 동시 요청을 구분하고 성공률·유효 JSON 비율·중앙값·95백분위 지연·메모리/오류 기록.
- 샘플에서 요구 조건 변경/허위 장소 0건, 핵심 추천의 AI 의존 0건. 지연 목표를 초과하면 기본 설명 즉시 제공하고 AI를 백그라운드 보조로 제한.
- 실제 사용자 이메일·토큰·비밀번호를 테스트 프롬프트나 공개 로그에 넣지 않음.

최초 동의 반영 이후, 사용자 요청으로 무료 `qwen3:4b`를 추가 설치하고 기존 8B를 보존한 채 모델당 47회씩 비교했습니다. 4B가 빠르지만 조건 손실과 두 모델의 미검증 정보 생성 문제가 있어 기본 모델은 변경하지 않았습니다. [모델 비교 및 S20+ 동의 검사 결과](LLM_COMPARISON_REVIEW.md)를 확인하세요. 유료 서비스 가입은 하지 않았고, 위의 설명 20개 이상·장기 안정성 목표는 아직 미달입니다.
