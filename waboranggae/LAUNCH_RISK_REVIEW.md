## 결론

현재 상태는 개발용 네이티브 시제품이며 출시 가능 판정은 **보류**입니다. 임시 공유 주소만 교체하면 해결되는 문제가 아닙니다. API·DB의 PC 의존성, 로그인 복구, 실제 경로 검증, 사용량 보호, 백업·복구 및 출시 패키지를 함께 보완해야 합니다.

무료로 고정 주소와 PC에 의존하지 않는 소규모 테스트 환경을 만들 후보는 있습니다. 다만 무제한 사용·무중단·장애 복구까지 보장하는 영구 무료 구성을 확인한 것은 아닙니다. 유료 서비스도 무장애를 보장하지는 않으며, 무료에서는 정지·쿼터·지원 제한을 특히 명확히 다뤄야 합니다.

## 2. 출시 전 해결해야 하는 위험

### A. 주소와 실행 환경 — 출시 차단

- `scripts/team-dev.mjs:86`, `:131`: 로컬 API와 Quick Tunnel을 백그라운드 자식 프로세스로 실행합니다. 이 스크립트에는 OS 부팅 시 자동 시작·프로세스 장애 자동 복구 관리가 없습니다.
- 현재 API·DB·LLM의 핵심 실행 장소는 사용자 PC입니다. 꺼짐·절전·회선 장애·프로세스 종료의 영향을 받습니다. 앞선 프로세스 종료 원인 자체는 확정하지 않았습니다.
- `android-native/app/build.gradle.kts:26`: API 주소를 APK에 넣습니다. 임시 호스트가 바뀌면 앱 주소, 서버 `PUBLIC_APP_URL`, OAuth Redirect URI, 웹 SDK 도메인 등 여러 설정이 어긋날 수 있습니다.
- 고정 IP 구입은 이 문제의 직접 해결책이 아닙니다. Quick Tunnel은 개발용 임의 주소이며 가용성 보장이 없습니다. [Cloudflare 공식 문서](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/)

필요 조치: 운영·개발 환경을 분리하고, 이름이 유지되는 HTTPS 엔드포인트와 서버 자동 복구를 마련합니다. 출시 APK에서 개발 암호·임시 URL을 거부하는 검사를 유지합니다. 서버 이전 때도 로그인 콜백이 유지되도록 주소를 관리해야 합니다.

### B. 소셜 로그인 복구와 오류 안내 — 출시 차단

- `server/src/auth/social.ts:12`: 진행 중인 로그인 상태를 메모리 `Map`에만 저장합니다. 서버 재시작·배포 또는 여러 서버로 요청이 나뉘면 인증 진행 정보가 사라집니다.
- `android-native/.../ui/AccountViewModel.kt:35`: 로그인 제공자 목록 조회 실패를 화면에 명확히 표시하거나 재조회하는 처리가 없습니다. 시작 때 연결이 안 되면 서버 복구 후에도 버튼을 제대로 사용할 수 없는 상태가 남을 수 있습니다.
- 같은 파일의 `task()`: 모든 HTTP 400을 비밀번호 규칙 오류로 설명합니다. 소셜 로그인·동의 오류에도 엉뚱한 안내가 나올 수 있습니다.
- `AccountScreens.kt`: 인증 창 열기가 추가 버튼으로 분리되어 있습니다. 외부 브라우저 열기 실패와 앱 복귀·프로세스 재생성 처리를 실기기에서 보완·검증해야 합니다. 현재 방식이 항상 실패하는 것은 아니지만 앱 복귀 안내에 의존합니다.
- `social.ts:85`, `AccountViewModel.kt`의 폴링: IP당 분당 100회 제한과 3초 간격 조회가 있습니다. 같은 Wi-Fi에서 여러 사람이 로그인하면 합산 제한에 걸릴 수 있습니다. 프록시 뒤에서는 클라이언트 IP 판별도 검증해야 합니다.

필요 조치: 로그인 임시 상태를 짧은 TTL의 공용 저장소(DB 등)에 안전하게 보관하고, 1회 소비·만료·재시작/중복 콜백을 검사합니다. 실패 원인별 메시지와 다시 시도, 앱 복귀 흐름을 추가합니다. 비밀값을 URL/로그에 노출하지 않는 현재 방향은 유지합니다.

실계정 최종 검증: 카카오·구글 각각 최초 가입/최초 동의/재로그인/자동 로그인/거부·취소/만료/앱 종료 후 복귀/탈퇴 후 토큰 거부. 제공자 콘솔의 실제 운영 상태와 등록 주소·서명 설정은 별도 확인이 필요합니다.

### C. 추천의 실제 이동 가능성 — 핵심 품질 차단

- `server/src/modules/recommendation/routing.ts:31`, `:63`: 추천 생성 시 `routeBetween()`은 항상 거리 기반 `estimateRoute()`를 반환합니다. 짧은 구간은 도보 속도, 긴 구간은 버스 속도·고정 대기시간 등으로 추산합니다.
- 실제 경로 조회는 `server/src/modules/maps/routes.ts:13`의 `/api/routes/segment`에서 요청할 때만 수행합니다. 이는 의도된 호출량 절약 구조이나, 추천 전체가 실제 운행 경로로 검증됐다는 의미는 아닙니다.
- 버스 정류소·노선 데이터가 존재해도 해당 출발 시각의 환승·배차·막차까지 보장하지 않습니다. 산·강·섬·외곽 지역에서 직선 거리 추정 오차가 커질 수 있습니다.
- 현재 카카오 도보·대중교통 REST 경로 조회는 공식 문서에 있고 이번 실제 구간 호출도 성공했습니다. API 자체가 없거나 전혀 미연결인 상태는 아닙니다. [공식 경로 API](https://developers.kakao.com/docs/ko/kakaomap/rest-api)

권장 개선: 후보 코스 생성 → 사용자가 선택한 코스의 구간만 실제 경로 조회 → 이동시간·식사·카페 순서·체류시간·총 시간을 다시 계산 → 조건에서 벗어나면 조정 또는 불충족 안내. 확인 불가 구간은 ‘미검증/예상’으로 남기고 실제 경로인 것처럼 그리지 않습니다. 단순히 식사·카페 기능을 없애서 해결하지 않습니다.

실제 경로를 반영한 뒤 뚜벅이 점수도 재계산해야 합니다. 점수 표준화 테스트 통과와 현장 이동 적합성은 별개입니다. 역 없는 지역, 터미널/사용자 선택 출발 좌표, 다중 코스 제목·지도 ID, 짧은 식사/카페 여행, 여러 날 코스도 함께 검증해야 합니다.

### D. 쿼터·과금·무료 서비스 정지 — 출시 차단

- `data/kakao.ts:29`: 카카오 보호 카운터는 `.runtime/kakao-usage.json`에 저장됩니다. 단일 프로세스 안에서는 예약을 직렬화하고 쓰기 실패 시 외부 호출을 중단하지만, 임시 파일시스템·복수 서버에서는 전체 사용량을 정확히 공유하지 못합니다.
- 현재 서버 카카오 보호 상한은 검색/경로를 합쳐 일 200회입니다. 서비스 제공자의 API별 무료량과 동일한 의미가 아닙니다.
- `middleware/rateLimiter.ts`: 기본 저장소는 프로세스 메모리입니다. 일반 API 제한은 GET을 제외하므로 이미지 같은 GET에도 별도 보호가 필요합니다.
- 서버 카운터는 앱·웹의 지도 SDK 직접 호출이나 같은 키의 다른 사용처까지 제한하지 못합니다. `.env`의 무료 확인 플래그만으로 실제 계정 과금 설정을 입증할 수 없습니다.

필요 조치: 공급자·API별 일/월 사용량을 DB에 원자적으로 예약, 로그인 사용자/게스트/IP별 제한, 동시 호출 상한, 중복 호출 합치기, 한도 임박 안내, 429/시간 초과 구분. 유료 추가 쿼터 및 자동 업그레이드 설정은 대시보드에서 확인해야 합니다.

현재 카카오 공식 무료 표에는 도보·대중교통 조회가 각각 일 1,000건이며, 개발자 계정에서 처음 활성화한 앱에만 카카오맵 무료 쿼터를 제공하는 조건이 있습니다. 현재 앱의 무료 자격과 다른 호출 사용량을 확인한 후 API별 여유량을 잡아야 합니다. 무조건 상한을 올리면 안 됩니다. [공식 쿼터·조건](https://developers.kakao.com/docs/ko/getting-started/quota)

- 프로젝트에서 정기 DB 백업·다른 장소 보관·복원 시험 자동화를 확인하지 못했습니다. Docker 볼륨 유지와 백업은 다릅니다.

- 정상 종료 신호 처리, 요청 마무리, DB 연결 정리, 배포 후 확인 및 되돌리기 절차도 운영용으로 정리해야 합니다.

필요 조치: 운영 DB 별도 생성, 개발자별 최소 접근권한, 암호화한 외부 백업, 실제 복원 검사, 마이그레이션 사전 검사. API 프로세스 생존 검사와 DB 포함 준비 상태 검사를 분리합니다. 개인정보 없는 오류 코드·지연시간·실패율 지표와 장애 알림을 추가합니다.

### G. LLM 지연·장애 격리 — 출시 전 보완

- `analysis/ollama.ts:6–10`: 기본은 로컬 Ollama/qwen3:8b, 90초 제한, context 4096, keep_alive 30m입니다. 지금 모델이 조회된다고 긴 시간의 추론 안정성을 입증하지는 않습니다.
- `TravelRepository.kt:60`: 추천 최대 135초, 설명 100초 등 긴 대기가 가능합니다. 응답이 없을 때 사용자는 앱이 멈췄다고 느낄 수 있습니다.
- 현재 버튼 중심 추천과 선택적 AI 설명 방향은 적절합니다. 다만 실패 시 빠른 대체, AI 동시 요청 수·대기열 상한·일시 차단/회복, 취소 전파가 더 필요합니다.
- 모델이나 실행기만 바꿔도 PC 꺼짐·호스팅 문제가 해결되지는 않습니다. 무료 상시 GPU 서버를 확보한 상태가 아닙니다.

무료 후보: Cloudflare Workers AI Free는 하루 10,000 Neurons를 제공하고 초과 시 요청이 실패합니다. 이는 ‘질문 10,000개’가 아니며 모델과 입력/출력 길이에 따라 소모량이 달라집니다. 오픈 가중치 모델별 한국어 조건 보존·설명 정확도·상업 이용 조건·데이터 처리 정책을 평가한 뒤 보조 AI에 한해 검토할 수 있습니다. 현재 Ollama와 호환 전환이 완료된 것은 아닙니다. [공식 Workers AI 요금](https://developers.cloudflare.com/workers-ai/platform/pricing/)

무료량이 없거나 AI가 느리면 추천 본체는 계속 동작하고 규칙 기반 설명을 즉시 보여 주는 쪽을 권장합니다. AI가 운행 정보·장소 사실을 만들어내지 않도록 검증 범위를 유지해야 합니다.

### H. 이미지·자료 권리·앱 패키지 — 출시 전 보완

- `media/routes.ts`: 허용된 관광 이미지 호스트와 응답 크기 제한은 있지만, 서버에서 매번 원본을 가져올 수 있습니다. 캐시 헤더만으로 모든 기기 간 원본 다운로드가 사라지지 않습니다. 이미지 요청 동시성·전송량을 점검하고 이용 조건에 맞는 썸네일·단기 캐시를 사용해야 합니다.

- `android-native/app/build.gradle.kts`: 현재 `0.1.0-pilot`, arm64/S20+ 검증용이고 release 작업을 명시적으로 차단합니다. 운영 서명/AAB/패키지명/버전/지원 기기/SDK 호환/개인정보 공개 페이지/스토어 정보가 완료되지 않았습니다.
- `STORE.md`의 Expo·iOS 중심 안내와 현재 native-only 목표가 달라 출시 문서를 정리해야 합니다. 기존 프로젝트를 지울 필요는 없습니다.

## 4. 권장 진행 순서

1. **코드의 확정 문제부터 무료로 보완**: 로그인 재시도/오류 문구/복귀, 로그인 임시 상태 공유, 토큰·탈퇴 보호, DB 준비 상태, 공급자별 사용량 제한, 선택 코스 실경로 재계산.
2. **현 프로젝트와 운영 후보를 분리**: 기존 웹·Expo·네이티브는 보존합니다. 테스트 DB와 가짜 계정으로 Supabase Free의 작은 API 이전·응답시간·동시접속 시험을 먼저 권장합니다. 무료 조건·개인정보 처리 위치를 수용할 때만 진행합니다. 성능/휴면 제약이 요구 수준과 맞지 않으면 전체 이전을 확정하지 않습니다.
3. **AI는 독립 보조 기능으로 유지**: 서버/DB를 클라우드로 옮겨도 개인 PC의 Ollama를 필수 호출하지 않습니다. Workers AI 무료 후보는 별도 평가하며 자동 과금 없이 한도 초과 시 대체 설명을 사용합니다.
4. **운영 설정은 한 번에 검증**: 고정 API 주소, 카카오/구글 콜백, 앱 서명·키, 개인정보/삭제 페이지를 같은 운영 환경 기준으로 맞춥니다. 사용자가 직접 해야 하는 계정 생성·본인 확인·약관·실계정 승인만 요청합니다.
5. **배포 전 장애 시험 통과**: 아래 표를 실제 운영 후보에서 수행하고, 결과 없이 ‘출시 준비 완료’로 표시하지 않습니다.

학교·팀·지원사업에서 관리되는 상시 서버를 무상 제공받을 수 있다면 기존 Node 구조를 유지하는 대안으로 함께 검토할 가치가 있습니다. 현재 그런 자원이 확보되어 있다고 가정하지 않습니다.
