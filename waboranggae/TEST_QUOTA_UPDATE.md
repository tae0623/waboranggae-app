# 최종 테스트용 호출 한도

2026-09-16 03:30 KST · 사용자 요청으로 비공개 최종 테스트 한도를 상향했습니다.

- Supabase 실제 설정: `KAKAO_DAILY_REQUEST_LIMIT=1000`. 설정값의 SHA-256 일치 확인.
- 기존 합산 300회 → **1,000회/일**. 코드의 기존 900회 상한도 1,000회로 조정.
- 로컬 `.env`와 `.env.edge.local`에도 1,000을 저장. 이미 켜 둔 로컬 서버는 재시작해야 환경변수가 적용됩니다. 휴대폰이 사용하는 클라우드 서버는 배포·반영 완료이며 APK 재설치는 필요 없습니다.
- 사용량 초기화 없음. 검증 직전 **300회**, 공개 장소 검색 2건 모두 실제 카카오 응답 HTTP 200, 검증 후 **302/1,000회**. 확인 시점 남은 합산 호출 698회이며 코스 수가 아닙니다.
- 무인증 보호 요청은 403 유지. 자체 JWT·비공개 입장 키·계정 및 DB 데이터·유료 요금제는 변경하지 않았습니다.
- 전체 자동 검사 **323개/39개 파일**, TypeScript 통과. 상한/음수/소수/잘못된 설정값 검사 9개 추가. 검사 결과: `.runtime/test-quota-check.json`.

현재 상한은 장소·주소 검색과 도보·대중교통 길찾기를 합산한 앱 내부 보호값입니다. [카카오 공식 무료 쿼터](https://developers.kakao.com/docs/ko/getting-started/quota)는 도보·대중교통 각각 일 1,000회지만, API별로 각각 1,000회씩 추가 허용하는 구조로 바꾸지는 않았습니다. 카카오 콘솔의 자체 쿼터·결제 설정도 변경하지 않았습니다.

로컬 파일 카운터와 클라우드 DB 카운터는 별개입니다. 같은 카카오 키를 쓰는 로컬/팀 환경에서 동시에 각각 최대량까지 테스트하지 말고, 이번 최종 테스트는 클라우드로 집중합니다. 다른 환경의 호출량·월간 쿼터는 카카오 콘솔에서 별도 확인해야 합니다.

## 공개 배포 전

- [ ] 최종 테스트 종료 후 운영 예상 사용량에 맞게 한도를 다시 결정해 반영.
- [ ] 무료 적용 배지·유료 API 미사용·다른 실행 환경의 동일 키 사용량 확인.
- [ ] 실제 초과/제공처 장애 화면 확인 및 운영 한도 문서 갱신.

운영 예제 기본값은 200으로 유지했습니다. 원스토어 출시 체크리스트에도 위 항목을 추가했으며, 공개 배포나 스토어 제출은 하지 않았습니다.
