# Galaxy S20+ 실계정 테스트 안내

검토일: 2026-09-15. 판정: 제한된 팀 실기 테스트 가능 / 스토어 제출 준비 완료 아님.
실제 휴대폰 조작과 카카오·Google 계정 동의는 사용자 담당입니다. 실기 통과했다고 기록하지 않았습니다.

## 지금 실행하기

1. S20+에 공식 Google Play의 Expo Go를 설치합니다.
   https://expo.dev/go?platform=android&device=true&sdkVersion=57
2. 휴대폰을 PC와 같은 공유기의 Wi-Fi에 연결합니다. PC는 유선 LAN이어도 됩니다.
3. PC에서 .runtime/phone-expo.svg를 열고 Expo Go의 QR 스캔으로 읽습니다.
4. 수동 입력 주소는 현재 exp://192.168.35.8:8082 입니다.
5. 새 와보랑께 화면에서 카카오/Google 로그인 → 인증 창 열기 → 본인 계정 로그인·동의 → 앱으로 돌아오기를 진행합니다.

현재 Expo/Metro 서버는 포트 8082, API는 8788, 개발 DB는 55432를 사용합니다.
Expo Go는 개발용 실행 도구입니다. 최종 서명 APK/AAB 및 Play 설치본과 동일한 배포 테스트는 아닙니다.
API는 HTTPS 터널을 사용하지만 Expo Go가 앱 코드를 받는 단계에는 같은 LAN이 필요합니다.
휴대폰의 localhost 또는 127.0.0.1은 PC를 가리키지 않습니다.
방화벽 문제가 생겨도 방화벽 전체를 끄지 마세요. 먼저 같은 공유기 연결과 PC의 8082 접근을 확인하세요.

### 모바일 Chrome으로도 테스트

https://qualification-excitement-flight-industry.trycloudflare.com

- 접속 이름: team
- 접속 암호: .runtime/TEAM_ACCESS.md 파일에서 확인합니다. 카카오/Google 비밀번호가 아닙니다.
- 이 방법은 PC/API/터널이 켜져 있으면 휴대폰이 다른 Wi-Fi나 LTE/5G여도 가능합니다.
- 브라우저 탭을 닫으면 웹 로그인 정보가 사라질 수 있습니다. 네이티브 앱은 SecureStore에 저장합니다.
- 팀 암호와 개발 QR/APK는 신뢰하는 테스트 팀 안에서만 공유합니다.

### 서버를 다시 켤 때

프로젝트 폴더에서 다음을 실행합니다.

    pnpm team:start
    pnpm app:dev --go --port 8082

다른 터미널에서 QR을 다시 만들 수 있습니다.

    pnpm phone:qr

API 코드 변경 후에는 pnpm team:restart, 팀 웹 화면 변경 후에는 pnpm team:build를 실행합니다.
PC IP 변경 시 QR 재생성, 터널 주소 변경 시 카카오 JS 도메인·카카오/Google 콜백·PUBLIC_APP_URL을 같이 갱신합니다.

계정 삭제는 복구할 수 없으므로 보관할 여행 정보가 없는 테스트용 앱 계정에서만 마지막에 수행하세요.
오류를 보고할 때는 시간, 기기/OS, 조작 순서, 오류 문구를 기록합니다. 비밀번호·API 키·토큰은 보내지 않습니다.
새 Google OAuth 앱이 테스트 상태라면 테스트 사용자 목록에 본인 Google 이메일이 있어야 합니다.

## 이번 검토에서 수정한 내용

- 다른 사용자 검색 이력 ID로 삭제 가능했던 권한 검사 누락 수정.
- 로그아웃 시 access/refresh 토큰을 서버에서 무효화. 현재는 모든 기기 로그아웃 방식.
- 계정/인증 응답 no-store, 팀 서버 내부 오류 메시지 숨김, 입력 길이·목록 개수 제한.
- bcrypt의 72바이트 초과 입력 제한, 취약 설치 의존성이 있는 bcrypt 5 → 6.
- 네이티브 토큰을 Android SecureStore에 저장. 늦은 갱신 응답의 로그아웃 복원 방지.
- 웹은 sessionStorage 사용. 민감한 토큰의 영구 localStorage 저장은 하지 않음.
- 북마크 전체 코스 snapshot, 검색 이력 preferences JSON 저장. 기존 데이터는 보존.
- 현재 추천의 실제 장소만 편집 가능. 출발지 고정, 서버에서 경로·시간·점수 재계산.
- TourAPI 유형 12 전체를 자연 관광으로 잘못 분류하던 문제 수정. 세부 분류 반영.
- 홈 해외 예시 사진을 실제 관광사진으로 연결. 기본 순위를 실시간 방문자 수처럼 보이게 하던 표시 수정.
- 팀 실계정 테스트에서는 시연 코스 자동 대체 비활성화.
- Expo SDK 57 권장 React Native 버전과 React 타입 정렬.

## 확인한 것과 미확인한 것

- 자동 테스트 19개 파일 · 101개 통과.
- root/web TypeScript 검사, 웹 빌드, Android+DOM 로컬 export 성공.
- TourAPI 실제 코스/사진, 카카오 구간 조회, 기상청 API 응답 확인. 해당 smoke test TMAP 호출 0회.
- 임시 테스트 계정 2개로 소유권 격리, 북마크 복원, 로그아웃 토큰 폐기, 계정 삭제 검증.
  검사에서 생성한 임시 계정만 삭제했고 기존 실제 사용자 데이터는 건드리지 않음.
- 웹 배포 번들에 서버 API 비밀키·DB/JWT 비밀값이 포함되지 않음을 검사.
- LAN 8082와 공개 HTTPS API 응답 정상. S20+ 자체에서의 실행은 아직 사용자 확인 필요.
- pnpm audit --prod 최종: critical 0 / high 0 / moderate 1.
  남은 uuid 7.0.3 권고는 Expo의 xcode 빌드 도구 의존 경로. 호환성 검증 없이 강제 메이저 변경하지 않음.
- Ollama는 연결되지만 이번 설명 생성 1회는 약 20,969ms 후 source=rules로 전환됨.
  AI 응답 품질/성능 합격 아님. 설명은 기본 규칙 문구를 먼저 보여 주므로 코스 화면 자체를 기다리게 하지는 않음.

## 스토어 출시 전 반드시 남은 일

1. 본인 실계정 OAuth 토큰 교환/신규 가입/재로그인, S20+ 종료·복귀·뒤로가기·네트워크 전환 실기 확인.
2. 서명된 독립 APK 및 Play AAB 생성/설치 테스트. 현재 PC의 표준 경로에서 Android SDK/JDK 빌드 도구가 확인되지 않음.
   eas.json preview는 APK로 준비했지만 EAS 로그인·외부 업로드·유료 빌드는 실행하지 않음.
3. 임시 trycloudflare 주소와 개인 PC 대신 고정 HTTPS 운영 API, DB 백업·복구·모니터링.
4. 운영자 SUPPORT_EMAIL, 최종 개인정보 처리방침, 데이터 보관/삭제 정책, Play 데이터 보안 양식.
5. 카카오 연결 해제 웹훅/탈퇴 시 공급자 연결 정리. 현재 수신 구현 없음.
6. 이메일 인증·비밀번호 재설정 이메일 발송 미구현. 테스트는 소셜 로그인 중심으로 진행.
7. 푸시 알림 미구현. 버튼에서 준비 상태를 명시하며 작동한다고 표시하지 않음.
8. 여러 서버로 늘릴 경우 OAuth 상태/요청 제한/쿼터/캐시를 공유 저장소로 이전.
9. 전체 코스 시간표는 여전히 추정 계산. 실제 배차, 영업시간, 휴무·입장 마감, 도서/장거리 접근은 현장 검증 필요.
10. 이전에 제목만 저장했던 북마크는 원본 코스가 없어 자동 복원 불가. 새로 저장하는 코스부터 전체 복원.
11. 저장 코스는 계획 기록이지 실시간 운영 보장이 아님. 예전 코스 편집은 다시 추천받은 현재 후보가 있어야 함.

새 개인 Google Play 계정의 경우 공식 문서상 최소 12명의 테스트 사용자가 연속 14일 참여하는 비공개 테스트 후 프로덕션 액세스 신청이 필요합니다.
현재 Expo Go/브라우저 테스트는 Play Console 비공개 테스트 참여 기간에 해당하지 않습니다.
