# 모바일 로그인 안내·코스 저장 오류 수정

## 원인

- 소셜 로그인 대기 문구가 인증 성공 후 지워지지 않았다. 코스 상세 화면이 모든 계정 메시지를 저장 오류 팝업으로 처리해, 로그인 완료 후에도 로그인 안내가 나타났다.
- 사용자가 확인한 저장 실패 코드는 HTTP 413이다. 지도 경로 좌표가 많이 포함된 코스 원본을 그대로 전송하면 서버의 128 KiB 요청 한도를 초과한다. 별도로 저장 스냅샷의 95,000자 제한도 있다.

## 수정

- 로그인 성공 시 진행 문구를 지우고, 계정 메시지와 저장 오류 상태를 분리했다. 저장 작업이 실제로 실패한 경우에만 저장 오류 팝업을 표시한다.
- 저장용 데이터가 클 때 지도 선 좌표만 Ramer–Douglas–Peucker 방식으로 간소화한다. 경로 양 끝점과 장소·일정·점수·이동 안내는 유지한다. 저장된 지도선만 간소화되며 화면에 열려 있는 추천 원본은 변경하지 않는다.
- UTF-8 기준 요청 110,000바이트 이하, 스냅샷 90,000자 이하인지 전송 전에 확인한다. 서버의 인증·크기 제한은 완화하지 않았다. 간소화 작업은 화면 스레드 밖에서 수행한다.
- 간소화해도 제한을 넘는 예외적인 데이터는 전송하지 않고 크기 안내를 표시한다. 로그인 오류로 안내하지 않는다.
- 홈 여행 소식 사진의 기간/수요 배지에서 눈 모양 이모티콘을 제거했다.

## 검증

- 서버·공유 로직 회귀 검사: 62개 파일, 573개 테스트 통과.
- Android 단위 검사: 105개 통과. 큰 경로의 용량 축소, 끝점·장소·점수 보존, 작은 코스 무변경, 초과 요청의 로컬 차단을 포함한다.
- Android 전체 재빌드와 Lint 통과. 변경된 생성자 때문에 오래된 증분 테스트 바이너리가 참조한 문제는 생성 산출물을 새로 빌드해 해소했다.
- S20+ 모의 화면 검사 4개 통과: 오래된 로그인 문구의 오표시 차단, 여러 날 추천, 저장 후 이동, 드래그·장소 추가.
- 별도 S20+ 실제 서버 검사 1개 통과: 임시 계정으로 로그인 → 큰 경로 원본의 저장용 변환 → 코스 저장 버튼 → 동선 화면 도착 → DB 저장 목록 재조회 → 장소·일정·점수 보존 확인.
- 해당 검사에서 원본 요청은 651,633바이트, 저장 후 조회한 스냅샷은 9,022바이트였다. 카카오 공급자 호출은 0회였다.
- 비공개 서버에 큰 저장 요청을 보낸 데스크톱 검사에서 413, 작은 저장·중복 저장에서 201, 목록 조회에서 200 확인. 휴대폰에서 의도적으로 원본 초과 요청을 보내는 초기 검사는 전송 시간 초과가 나서, 최종 휴대폰 검사는 수정된 요청의 실제 성공에 집중했다.
- JSONB/JavaScript 왕복에서 화면용 소수 좌표의 약 1e-13 차이가 있어 실제 DB 비교는 숫자 1e-9 이내 차이를 허용했다. 문자열·장소 순서·시간·점수 필드 삭제는 허용하지 않았다.
- APK/소스의 현재 알려진 서버 비밀값 검출 0. 검사에서 카카오 검색·길찾기 호출 0회.
- 임시 테스트 계정과 그 북마크는 검사 후 삭제했다. 실제 사용자 계정·로그인 저장 옵션·코스는 변경하지 않았다.

## 전달 상태

- 수정된 테스트 APK를 연결된 S20+에 덮어 설치했다.
- 이번 수정은 모바일 범위다. 웹·서버 코드 재배포, GitHub 업로드, 공개 서버 전환, 원스토어 제출은 하지 않았다.
- 이전과 같은 비공개 테스트 앱이며 정식 출시 준비는 보류 상태다.
