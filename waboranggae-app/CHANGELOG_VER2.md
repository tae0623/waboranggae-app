# 와보랑께 ver2 변경 요약

## 서비스 방향

- 자가용 없이 전남을 여행하는 사용자가 출발지, 시작 시간, 체류 시간, 식사, 이동 강도, 동행, 관심사를 직접 선택하는 흐름을 기본으로 구성했습니다.
- 자연어 AI는 선택 조건을 빠르게 채우는 보조 기능으로 두었습니다.
- 버튼 추천은 응답 속도와 재현성을 위해 시간 규칙+검증을 기본으로 사용하며, LLM 코스 계획은 환경변수로 켜는 비교 실험 기능으로 분리했습니다.
- 추천 장소는 한국관광공사 TourAPI 응답만 사용하고, LLM은 이 후보의 순서를 제안하거나 추천 이유를 설명합니다.
- 서버가 식사 시간, 연속 음식점·카페, 일정 길이, 장소 중복, 이동 거리 등을 다시 검증하므로 LLM이 임의의 장소나 무리한 일정을 확정하지 못합니다.

## 주요 개선

- 시작 시간과 점심·저녁 선호 조건을 추가했습니다.
- 점심은 11:30~13:30, 저녁은 17:30~19:30 범위와 일정 중첩 시간을 기준으로 배치합니다.
- 역·터미널·숙소 선택과 실제 출발지 문자열을 동기화하고, 식사가 포함되면 첫 카페를 식사 다음에 배치합니다.
- 식당 연속 배치, 장소 중복, 지나치게 짧거나 긴 일정, 이동 강도에 맞지 않는 거리의 코스를 차단합니다.
- 선택한 여행 길이와 30분 이상 차이 나는 2~8시간 코스는 차단하고, 인근 관광 후보와 체류시간을 함께 조정해 선택 시간에 맞춥니다.
- 긴 코스는 관심사 후보가 부족해도 가까운 일반 관광지를 보충 조회해 장소 수를 확보하며, 체류시간만 과도하게 늘리지 않도록 종류별 상한을 적용합니다.
- Ollama 코스 생성 실패나 검증 실패 시 동일한 TourAPI 후보로 규칙 기반 코스를 구성합니다.
- 코스별로 `AI+검증`, `규칙+검증`, `시연 데이터` 출처를 구분해 표시합니다.
- 추천 결과 필터, 실제 장소 이미지·주소, 실제 좌표 기반 지도, 공유 기능을 연결했습니다.
- 동선 탭에서 추천 코스가 2개 이상이면 코스 선택 버튼을 표시하고, 선택한 코스에 맞춰 지도·방문 순서·다음 목적지를 함께 바꿉니다.
- 코스 제목은 LLM의 자유 생성에 맡기지 않고 실제 대표 관광지와 테마를 조합하며, 같은 제목이 생기면 다른 경유지를 반영해 고유하게 만듭니다.
- 지도 관광지 마커는 PC에서 마우스를 올리거나 모바일에서 탭하면 TourAPI 이미지·장소명·도착시간·주소·설명을 표시합니다. HTTP 이미지와 앱 내 지도의 보안 정책 충돌은 허용 호스트만 통과시키는 서버 이미지 프록시로 해결했습니다.
- 역이 없는 지역은 터미널·숙소·직접 입력을 사용할 수 있으며, 완도항 같은 명시 출발지는 LLM이 터미널로 바꾸지 못하도록 서버가 원문 조건으로 재검증합니다.
- 자연어에 명시된 출발지·시간·여행 길이·이동 강도·식사·관심사는 LLM 결과보다 우선 적용합니다.
- 추천·공공데이터 조회 캐시와 중복 요청 합치기, API 호출 제한, 운영 환경 비밀키 검사를 추가했습니다.
- `apis.data.go.kr` 계열은 서버의 `DATA_GO_KR_KEY`를 공통으로 사용하고 API별 활용승인 결과만 노출합니다.
- TAGO 정류소 거리와 고유 경유노선 수를 대중교통 접근성에 반영하고, 노선 API 사용 가능 시 대표 배차간격까지 보강합니다. 실제 길찾기는 계속 TMAP이 담당합니다.
- Android/iOS 앱 식별자, 버전, 권한, 아이콘, 스플래시, EAS 빌드 프로필을 구성했습니다.

## 심사 제출 자료

- `ARCHITECTURE.md`: TourAPI·Ollama·검증기·앱의 역할과 운영 배포 구조

- TourAPI 후보 추천 → 일정 검증 → 설명 생성 전 구간 테스트
- 실제 6시간 버튼 조건에서 TourAPI 4개 장소·예상 6시간 결과 확인
- 실제 TMAP 대중교통 길찾기 응답과 구간 시간·도보 시간·경로 형상 파싱 확인
- Prisma 스키마 및 마이그레이션 파일 검사

## 실제 스토어 등록 전 필수 작업

1. API 서버, PostgreSQL, Ollama를 HTTPS가 적용된 상시 서버에 배포합니다.
2. EAS production 환경의 `EXPO_PUBLIC_API_BASE_URL`을 운영 API 주소로 설정합니다.
3. `PRIVACY_POLICY.md`의 운영자 연락처를 실제 정보로 교체하고 공개 URL을 만듭니다.
4. 실제 기기에서 네트워크, 공유, 지도, 느린 LLM 응답을 최종 확인합니다.
5. Google Play 또는 Apple App Store 개발자 계정에서 빌드 파일과 심사 정보를 제출합니다.

스토어 링크는 심사 승인 후 생성되며, 계정 소유자의 등록·결제·심사 제출이 필요합니다.
