> 후속 작업: 아래는 재배포 전 감사 시점의 기록이다. 사용자 요청에 따른 재배포·휴대폰 재설치와 후속 검사(406개)는 [ver5 배포 기록](VER5_DEPLOYMENT_2026-09-16.md)을 확인한다. 공개 출시 준비 판정은 여전히 보류다.

검토일: 2026-09-16 KST. 대상: 이 폴더의 Kotlin 네이티브 Android, 공통 API 서버, web.

**판정: 아직 공개 출시 준비 완료가 아니다.** 카카오 보호 한도와 별개로 출시용 서명, 공개 API 운영 전환, 계정 보안, 최종 개인정보 정책, 스토어 승인이 남아 있다. 단위 테스트 통과는 무취약성이나 스토어 승인을 보장하지 않는다.

- 장소 자동완성에서 호출되지 않던 `searchNominatim`과 전용 상수.

전체 프로젝트, 기존 Expo 프로젝트, DB 데이터, 실제 사용하는 지오코더·편의시설 모듈은 삭제하지 않았다. Expo는 이전에 요청한 보존 원칙을 따른다. 미사용 판정만으로 외부 팀원이 사용할 수 있는 개발 도구 전체를 제거하지 않았다.

### 의존성 취약점은 ‘0건’이 아님

- 루트 `pnpm audit --prod`: 중간 1건(`uuid@7.0.3`, Expo → xcode 경로), 높음/치명적 0. [공급자 공지](https://github.com/uuidjs/uuid/security/advisories/GHSA-w5hq-g745-h8pq)
- 별도 Edge 빌드 폴더 `npm audit --omit=dev`: 높은 위험도 **5개 패키지 경고**. 근본 공지는 `deepmerge-ts`, `effect` 두 계열이며 Prisma 도구/설정 경로로 전파된다. 5개의 서로 다른 직접 공격 취약점이라는 뜻은 아니다.
- 새 번들 입력 목록에서 `uuid`, `xcode`, `deepmerge-ts`, `effect`, `@prisma/config`의 포함은 **0개**. 해당 공지의 실행 경로가 현재 서버 번들에 포함되지 않았다는 제한된 확인이다.
- 보관 중인 Expo/Prisma 빌드 환경 경고는 남아 있다. 자동 major upgrade/강제 override로 숨기지 않았으며, 호환 버전으로 별도 정비 후 빌드 재검증해야 한다. npm 검사는 Android Maven/Kakao SDK 취약점 전체 검사를 대체하지 않는다.
- 로컬 `.env` DB URL은 예제의 개발용 기본 계정이다. 유출 탐지 결과와 분리했다. 운영 Supabase에는 별도 계정을 사용하며, 이 개발 계정을 외부에 노출하면 안 된다.

## 4. 노션 안내와 제출 준비 대조

[공식 안내](https://lowly-polyanthus-1fb.notion.site/2026-36b5dce406e380e0a3d1f80525667a11)를 브라우저에서 읽었다. 페이지나 계정은 수정하지 않았다.

- **공식 마감: 2026-09-21 16:00 KST.** 사용자 목표인 9/20 등록 완료는 내부 마감으로 유지한다.
- 앱은 최소 1개 스토어 **승인·등록 완료 링크**가 필요하다. APK만 준비하거나 심사 접수만 한 상태로 충족한다고 판단하면 안 된다. 추가 등록기간은 없다.
- 지정 기능설명서 양식을 사용해 PDF로 제출한다. 대표 이미지 1장, 상세 이미지 3~5장, 핵심 기능 최대 5개 흐름, 지역 특화·API 활용·차별성·발전계획을 실제 구현과 맞춘다. 문서 자체는 이번에 작성하지 않았다.
- 팀명/대표 변경 제한을 확인하고 최종 팀원 정보를 확정한다. 앱 이름은 뚜버기로 바뀌었지만 접수상의 팀명을 자동 변경하는 것은 아니다.
- 개인 로그인 계정을 심사용으로 제출하지 않는다. 게스트로 확인 가능한 기능과 계정 기능을 구분한다. 별도 계정이 필요하면 안내의 `openapi` 또는 `openapi@메일도메인` 형식과 지정 비밀번호를 사용한다. **현재 일반 가입의 대문자 요구가 지정 비밀번호와 충돌**하므로 일반 정책을 통째로 완화하지 말고, 권한 없는 전용 심사 계정을 관리 절차로 준비할지 결정해야 한다. 이번에 생성하지 않았다.
- 실제 활용한 한국관광공사 API, 신청자, 인코딩/디코딩 인증키 정보를 공식 제출 화면에서 준비한다. 키는 GitHub/일반 기능설명서/채팅에 쓰지 않는다. 제출 항목에는 대표 API 운영계정 신청이 선택으로 명시되어 있으므로 일반 FAQ의 예전 의무 표현과 구별한다.
- 공사 OpenAPI 사용은 필수다. 현재 관광정보 API 실호출 + 단기 메모리 캐시를 사용하며, 카카오만으로 대체하지 않는다. 호출 이력과 기능별 사용처를 제출 자료에 매핑한다. 관광정보를 영구 DB 복제본만으로 제공하도록 변경하지 않았다.
- 평가 비중: 기획 30, 완성도 30, 데이터 20, 발전성 20. 지금은 신규 AI 기능 확대보다 장애 없는 추천·수정·지도·계정과 제출 증빙에 우선순위를 둔다. 클라우드 Ollama는 꺼져 있으므로 항상 AI가 코스를 생성하는 서비스로 설명하면 안 된다.

개인위치정보 단말 내부 사용 관련 FAQ는 현재 설계 방향과 부합하지만, 신고 필요 여부를 최종 법률 판단한 것은 아니다. 사용자가 직접 입력한 집 주소/저장한 출발지도 개인을 식별할 수 있으므로 별도 보호 대상이며, GPS를 보내지 않는다는 사실만으로 모든 위치 관련 의무가 사라지는 것은 아니다.

## 5. 현실적인 진행 순서

1. **즉시:** ONEconsole 계정/본인 확인 완료 상태, 최종 패키지·서명 관리 방식, 운영 정책을 확정한다. 개발자가 대신 가입/약관 동의/스토어 제출하지 않았다.
2. **공개 전:** 공유 요청 제한·토큰 재사용 방어·재인증 등 계정 보안 항목을 해결하고 검증한다. 그 뒤 비공개 서버를 공개 운영 설정으로 전환한다.
3. **최종 APK:** release 빌드 → S20+와 다른 Android 버전에서 설치/업데이트/오프라인/권한 거절/로그인 만료/지도 복귀/계정 삭제 검사. 무료 지원 도구로 가능하나 사용자 실계정 인증은 직접 진행한다.
4. **스토어:** 아이콘·스크린샷·소개·개인정보 URL·문의처·권한 사유·심사 안내와 서명 바이너리를 제출, 반려 대응 후 실제 설치 링크 확인. [ONE store 바이너리 가이드](https://onestore-dev.gitbook.io/dev/docs/apps/product/android/binary), [배포 상태 안내](https://onestore-dev.gitbook.io/dev/docs/apps/product/android/displayed-info).
5. **9/20 내부 마감:** 타인의 새 기기·다른 네트워크에서 스토어 설치부터 끝까지 확인. 9/21 16시 이전 지정 양식/키/링크/계정 제출 및 접수 확인. 원스토어 승인 완료일은 보장할 수 없다.

스토어 등록이 일정상 불가능해지는 경우, 안내에 웹 서비스 URL 제출 방식도 있다. 다만 실제 웹 완성도와 동일 서비스 요건을 확인한 뒤 **사용자가 제출 유형을 결정해야 하며**, APK를 임의로 SW 유형으로 바꿔 제출하는 우회는 하지 않는다.
