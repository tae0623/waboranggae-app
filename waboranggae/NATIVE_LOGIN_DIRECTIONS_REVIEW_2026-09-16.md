별도 유료 이미지 서비스나 새 API 키는 추가하지 않았다.

## 서버와 DB

- 로그인별 sessionId를 액세스·갱신 토큰에 부여하고, 갱신 시 같은 ID 유지.
- auth_revocations에는 세션 ID의 SHA-256 해시와 만료 시각만 저장. 원문 토큰·이메일 없음.
- 마이그레이션 20260916010000_current_session_logout 적용.
- 해당 테이블 RLS 활성화, PUBLIC/anon/authenticated 접근 차단, 기존 제한된 서버 계정만 접근.
- 기존 테이블 8/8 확인, RLS 미적용 0, 공개 클라이언트 테이블 권한 0. TLS 인증서 검증 유지.
- 기존 웹에서 명시적으로 사용하는 전체 로그아웃 /auth/logout 동작은 호환성을 위해 유지.
- sessionId가 없는 구형 토큰은 갱신 시 새 세션으로 전환. 구형 토큰을 일괄 폐기하거나 모든 사용자 로그인을 강제로 끊지는 않음.
- Supabase 함수 version 33 ACTIVE. 첫 배포 시 일시적 502가 있었으나 동일 코드 재시도로 완료.
- 인증 없는 보호 API 요청은 HTTP 403 유지. 새 비밀값 업로드 없음.
- 실제 클라우드 테스트: A/B 두 로그인 중 A 로그아웃 후 A 액세스·갱신 401, B 액세스·갱신 200.
- 검증용 example.invalid 계정만 생성 후 삭제. 기존 사용자 계정은 변경하지 않음.

## 검증

- 서버: 41개 파일 / 342개 테스트 통과. TypeScript --noEmit 통과.
- Android: 10개 스위트 / 단위 테스트 71개 통과. 앱·테스트 APK 빌드 성공.
- Android lint: 오류 0, 경고 24. 경고가 모두 해소된 상태는 아님.
- 여행지 선택 UI: 가나다순, 선택 후 반영, 닫기, 1.5배 글꼴 조건에서 마지막 화순까지 접근·선택 확인.
- 로그인 UI: 배경 사진 로딩, 실제 출처 조건부 표시, 이메일 기억, 자동 로그인 체크, 공식 로고, FLAG_SECURE 확인.
- 실제 휴대폰 계정 테스트: 가상 이메일 계정 로그인 → 저장 설정 → 새 Repository에서 자동 로그인 복원 → 현재 세션 로그아웃 → 다른 세션 유지.
- 길찾기 Intent의 명시적 시작/끝 좌표와 방식을 검증. S20+에 외부 카카오맵 앱이 설치돼 있지 않아 그 앱 내부 수신 화면은 검증하지 않음. 웹 URL 생성은 단위 테스트 통과.
- 소셜 공급자의 실제 개인 계정 로그인은 이번 변경에서 수행하지 않음.
- S20+ 최종 회귀 테스트 14개 모두 통과(71.428초). 테스트 건너뜀 없음. 실제 홈 이미지 → 출발 장소 검색 → 추천 API → 두 번째 코스 지도·이미지 흐름도 통과.
- 로그인 화면은 캡처하지 않음. 지역 선택 화면만 가상 지역 목록으로 캡처·확인.
