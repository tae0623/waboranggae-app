# Android → 웹 동기화 (2026-09-16)

대상: `ver5`의 `waboranggae/web`, 고정 팀 웹 `https://waboranggae-app.pages.dev/`.
Android의 현재 Kotlin 화면·요청 변환·API 호출을 기준으로 웹의 오래된 동작을 맞췄습니다. Android APK와 Supabase 서버·DB 설정은 이번 변경에서 수정하지 않습니다.

## 자동 로그인 보안

- 팀 접속 인증과 개인 계정 로그인은 별개입니다. 팀 인증을 통과해야 모든 페이지와 API에 접근할 수 있습니다.
- 로그인 유지 선택 시 갱신 토큰을 AES-GCM으로 암호화한 `HttpOnly; Secure; SameSite=Strict` 쿠키에 저장합니다. JavaScript에는 실제 갱신 토큰 대신 표식만 반환합니다.
- 암호화 문맥을 팀 주소·접속 암호·팀 연결 만료일에 묶습니다. 쿠키 유효기간은 최대 7일이며 팀 연결 만료보다 길지 않습니다. 서버의 실제 세션 만료/폐기 검사도 그대로 적용됩니다.
- 선택하지 않으면 지속 쿠키를 만들지 않습니다. 일반 API/네이티브 클라이언트의 인증 형식은 바꾸지 않습니다.
- 서로 다른 탭의 로그인 세션 ID가 다르면 갱신을 거부하며 다른 탭의 쿠키를 지우지 않습니다. 웹 세션 조회/해제 요청에 각각 10초/5초 제한을 둡니다.
- 아이디 저장을 선택한 이메일만 로컬 저장소에 남습니다. 비밀번호는 저장하지 않습니다. 일반 웹 저장소에 장기 갱신 토큰을 보관하지 않습니다.
- 고정 Pages 게이트웨이가 없는 직접 Vite 미리보기에서는 자동 로그인이 비활성화됩니다. 개발 서버 인증 암호·관광 API 키·DB 암호를 프론트엔드에 넣지 마세요.

## 플랫폼 차이 / 검증 제한

- GPS는 외부에 전송하지 않습니다. 비공개 팀 웹은 기존 `Permissions-Policy: geolocation=()`을 유지하므로 위치 권한이나 가까운 순 GPS 보정은 제공하지 않습니다. 검색 결과는 정확도순이고 지도에는 검색·선택 장소만 사용합니다.
- 웹은 브라우저 탭을 임의로 종료하지 않습니다. Android의 시스템 뒤로가기/앱 종료는 네이티브 전용입니다.
- 카카오맵 외부 길찾기는 도보/대중교통 링크이며, 웹 내부 시간표 갱신은 전체 코스의 서버 `refresh-route`로 통일합니다. 별도 구간 조회로 지도만 바뀌고 총시간은 그대로 남는 오래된 웹 동작을 제거했습니다.
- 음식점 영업 여부를 보장하지 않습니다. 방문 전 확인 문구를 유지합니다.
- 카카오 일일 보호 한도가 소진된 날에는 실제 새 추천·경로 성공을 확인할 수 없습니다. 테스트를 위해 보호 한도를 초기화하거나 우회하지 않았습니다.
- 실계정 카카오/Google 인증 완료는 이용자의 직접 인증이 필요합니다. 공급자 설정 조회와 테스트 계정 API 검증은 실계정 OAuth 완료 검증을 대신하지 않습니다.

## 검증

- 전체 회귀 테스트 491개 통과(신규 웹 동기화/보안 테스트 26개 포함).
- 루트/웹 TypeScript 검사, 웹 미사용 선언 검사 통과.
- `node scripts/build-pages.mjs` + `node scripts/verify-pages-build.mjs` 통과. 브라우저 번들 비밀값 및 게이트웨이 우회 검사 0건.
- 현재 Git 대상의 알려진 서버 비밀값 및 비공개 설정 파일 노출 검사 0건. 모든 취약점/과거 Git 이력에 대한 보증은 아닙니다.
- 로컬 UI 테스트 데이터로 360×800 화면에서 로그인 디자인, 행사 포함, 출발지 검색, 달력, 12시간 선택, 목적/식사, 추천 2개, 코스 전환, 초과 미리보기, 사진/날씨 표시 확인.
- UI 테스트 데이터는 `.runtime`에만 두며 배포·GitHub 업로드 대상에서 제외합니다.
