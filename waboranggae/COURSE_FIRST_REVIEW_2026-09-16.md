# 코스 우선 추천 전환 — 2026-09-16

## 반영한 흐름

출발 장소 → 여행 지역·날짜·현지 시작 시각 → 걷기/속도·목적·식사 → 코스 추천 → 장소 제외·순서 편집 → 동선 재계산.

- 기본 입력에서 총 여행 시간과 필수 종료 시각을 제거했다.
- `종료 시간 제한`은 기본 꺼짐이며, 켠 경우에만 같은 날의 종료 시각을 서버로 보낸다.
- 신규 Android와 web은 `scheduleMode: course-first`를 사용한다. 이전 클라이언트는 기존 고정 시간 계약을 유지한다.
- 호환용 `durationHours` 기본값 6은 신규 방식의 제한 시간이 아니다. 2 또는 8로 보내도 신규 방식의 일정 길이·장소 수는 바뀌지 않는 회귀 테스트를 추가했다.
- 시작 시각은 식사 배치와 여행일 시간대별 날씨 조회에 사용한다. 날씨 종료 시각은 실제 추천/편집 코스의 예상 종료 시각으로 계산한다.
- 일반적인 초기 후보는 속도에 따라 3~5곳을 목표로 하되, 데이터·동선에 따라 더 적을 수 있다. 같은 날을 넘기지 않는다.
- 선택 시간을 채우기 위한 체류 시간 부풀리기와 최소 총시간 미달 거부를 신규 방식에서 제거했다. 체류 시간 자체는 장소 유형별 추정치다.
- 실제 경로 반영 후 조건이 맞지 않으면 최대 4회의 축소 후보 검증을 한다. 초기 추천에서는 필수 방문지·명시적으로 선택한 식사를 몰래 제거하지 않는다.
- 편집 화면에서는 한 곳까지 남길 수 있다. 사용자가 식당 또는 필수 방문지를 직접 제외했다면 그 편집에만 해당 조건을 해제한다. 원래 추천 요청은 변경하지 않는다.
- 편집·새로고침 모두 서버가 가진 추천 장소 ID만 허용한다. 장소·순서에 맞춰 경로, 도착 시각, 총시간, 점수, 코스 제목을 다시 계산한다.
- 현지 코스 시간과 도시 간 이동은 계속 분리한다. 실제 단말 위치를 서버로 보내는 기능은 추가하지 않았다.

순천 291분 코스에서 카페 한 곳만 남기면 56분으로 재계산됐다. 식사 제외, 한 장소, 경로 구간 수, 합계, `requestedMinutes` 미전송, 이후 경로 새로고침 성공까지 확인했다.

강진처럼 짧은 대안이 높은 점수로 앞서는 경우를 보고, 이후 추천 정렬을 보완해 실제 경로 확인 조건이 같은 경우 3곳 이상의 코스와 2곳 코스를 단일 장소 대안보다 먼저 제시한다. 더 적은 장소를 금지하지는 않는다.

S20+의 실제 API 흐름은 새 시간 입력 → 실제 추천 → 두 번째 코스 지도·경로 표시까지 확인했다. 이후 계측 검사가 사진이 원래 없는 카카오 장소에도 사진 로딩을 기다려 중단됐다. 검사 조건을 수정했으며, 전체 LiveFlow 재실행은 아래 호출 한도로 완료하지 못했다. 단일 장소 편집 UI는 별도 계측 검사로 통과했다.

## 배포 및 설치

- 기존 본인 Supabase 검증 API에 코드만 재배포했다. 비밀값·유료 설정·호출 한도·인증 범위는 변경하지 않았다.
- 최종 서버 번들 식별자: `72d6a47c27d88129`.
- 동일 `app.mjs` 파일명으로 배포된 새 소스가 확인돼도 실제 응답은 이전 계약을 유지하는 현상을 발견했다. 빌드 결과의 콘텐츠 해시를 파일명과 import에 반영한 뒤 새 계약이 동작함을 확인했다. 배포 스크립트에도 import 파일 해시 검증을 추가했다.
- S20+에 `install -r`로 최신 APK를 설치했다. 사용자 데이터는 지우지 않았다.
- APK: `android-native/app/build/outputs/apk/debug/app-debug.apk`.
- 아직 비공개 검증 서버/디버그 APK다. 스토어 공개 출시 완료를 뜻하지 않는다.
