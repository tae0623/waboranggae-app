# 보안 검토 기록 (2026-09-15)

대상: ver4-review 작업 폴더의 Express API·웹·Kotlin 네이티브 시제품.
이 문서는 범위 내 코드 검토와 자동 검사 결과이며, 침투 테스트·무유출 보증·출시 승인서가 아닙니다.
기존 문서의 “로그인 없음”, “XSS 위험 없음” 같은 단정은 현재 구조에 맞지 않아 대체했습니다.

## 이번에 적용한 조치

- 네이티브 갱신 토큰: Android Keystore AES-GCM 암호화, noBackupFilesDir, AtomicFile 저장.
- 액세스 토큰·비밀번호는 메모리에만 유지. 로그인 화면 FLAG_SECURE, 일반 저장 상태에 비밀번호를 넣지 않음.
- HTTPS·동일 API 출처만 사용. 외부 이미지/소셜 인증 주소에 API 인증 헤더를 넣지 않음.
- OAuth는 외부 브라우저 + 서버 교환 + 임의 flowId/별도 pollSecret + 만료/1회 결과 수령. Google PKCE 적용.
- 계정과 이력 삭제는 인증 사용자 ID로 한정. 계정 삭제 시 관련 DB 행 cascade 삭제.
- 최초 계정 이용 동의 버전·시각 기록, 같은 버전 재로그인 시 기록 유지, 미동의 계정 새 쓰기 서버 차단. 기존 정보 조회/삭제와 게스트 이용은 유지.
- 신규 사용자 계정은 동의 전 생성하지 않음. 인증 중 임시 식별자는 AES-256-GCM으로 DB 암호화 저장, 5분 만료·매분 정리 (서버 중단 시 재개 후 삭제). 낙관적 잠금으로 결과 수령/동시 동의 1회 처리. 실계정 제공자별 외부 개인정보 처리 검증은 남음.
- OAuth·API 호출량 공유 테이블과 계정/이력/마이그레이션 테이블에 RLS 및 공개 클라이언트 권한 제거. 로컬·새 Supabase DB에 적용/검사 완료. 사용자 확인으로 Supabase 공개 Data API 비활성화. 운영 API/DB 주소 전환은 아직 전.
- 운영 카카오 호출량을 원자적 DB 예약으로 제한하고 저장소 장애 시 외부 호출 차단. 다른 외부 API 전체의 과금 방지를 보장하는 것은 아님.
- DB 연결/필수 테이블 확인 후 /readyz 정상 판정, 실패 시 503. 운영 환경에서 임시 터널·개발 키·데모 fallback·전체 프록시 신뢰 차단.
- 선택적 Ollama 추론은 동시 1건, 설정 기본 15초/최대 20초, 2회 연속 실패 후 30초 중단. 실제 모델 품질/클라우드 성능 검증과 별개.
- 여행 이력 자동 저장 중단 및 명시적 저장 확인.
- JWT 검증 알고리즘 HS256 제한. 비밀번호 bcrypt 해시 및 72바이트 한계 검증 유지.
- 인증·일반 API 오류 로그에서 내부 오류 메시지 원문 제거 (쿼리·개인정보·키 포함 URL 노출 방지).
- 관광 이미지 프록시: 정확한 허용 호스트, URL 인증정보·비표준 포트 거부, 리다이렉트마다 재검증,
  SVG/HTML 제외한 래스터 MIME만 허용, 스트림 수신 중 8MiB 제한.
- 추천 캐시의 만료 좌표 키 정리 및 최대 200건 제한.
- APK에 서버용 TourAPI/DB/JWT/OAuth 비밀값을 넣지 않음. 개발 접속 키와 카카오 클라이언트 키는 APK에 존재하므로 공개 금지.

## 잔여 위험 / 출시 전 작업

1. 현재 API/DB/LLM은 이 PC와 임시 HTTPS 터널에 의존합니다. 고정 배포·방화벽·백업·모니터링·비밀값 관리 필요.
2. 갱신 토큰의 서버 측 1회용 회전/재사용 탐지, issuer/audience, 계정 삭제 직전 재인증을 추가 검토해야 합니다.
   현재 로그아웃은 tokenVersion 증가로 **모든 기기**를 철회합니다.
3. 이메일 소유 확인·비밀번호 재설정 절차는 미구현. 테스트용 이메일 가입을 공개 정식 가입 준비 완료로 보지 않습니다.
4. 실제 카카오·구글 계정 인증·취소·연결 해제·탈퇴 및 공급자 콘솔 설정은 사용자가 직접 최종 검증해야 합니다.
5. 웹 sessionStorage 토큰은 XSS에 면역이 아닙니다. CSP/출력 검토와 별도 동적 보안 검사가 필요합니다.
6. 네이티브 키 저장은 잠금 해제된 기기·루팅·악성 OS·디버깅 환경까지 보호한다고 보장하지 않습니다.
7. 전체 의존성 취약점/SDK 데이터 수집 목록, Play 데이터 보안 양식, 로그·백업 파기·국외 처리 공개 미완료.
8. 출처 표기는 저작권 허락을 대체하지 않습니다. 사진별 라이선스 및 팀 로고/원화 권리 확인 필요.
9. 세부 계정 삭제 보안 강화 전 릴리스 빌드는 계속 차단합니다.

## 검증 범위

TypeScript(서버/웹), Vitest 회귀, Android 단위 검사, Android Lint, S20+ 생성형 임시 계정 로그인·저장·로그아웃,
계정 삭제 후 토큰 거부, 실제 추천/상세/두 번째 지도 전환을 검사했습니다.
정확한 실행 결과와 남은 범위는 `android-native/VALIDATION.md`와 `NATIVE_RESTORATION_REVIEW.md`를 확인합니다.
기존 실제 사용자를 대상으로 삭제·개인정보 열람 시험을 하지 않았습니다.
