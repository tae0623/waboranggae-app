## 시간 계산과 실제 발견한 오류

현지 코스 시간 = 도착 거점→첫 장소 이동 + 장소 간 이동 + 방문 체류 + 대기/휴식. 외부 도시에서 도착 거점까지의 이동은 여기에 더하지 않습니다. 같은 도시 내 출발지는 기존처럼 첫 장소까지 이동을 포함합니다. `local`을 보내지 않는 기존 클라이언트의 시간 의미는 유지합니다.

- 도시 간 출발지는 이름만 바꾸지 않고 별도 객체로 보존. 여행 도시 거점은 카카오 검색 결과의 주소를 검증해 사용하며, 역이 없으면 버스터미널을 찾습니다.
- 기존 계산의 최대 30분 초과 허용은 현지 모드에서 적용하지 않습니다. 실제 이동 시간에 맞춰 체류를 조정하되 장소별 최소 체류는 유지합니다. 충족 불가한 코스는 충족한 것처럼 표시하지 않습니다.
- 나주 6시간은 TourAPI가 정상인데도 식당 후보가 앞단의 거리순 자르기에서 빠져 계획이 0개가 되었습니다. 계획용 후보 풀과 최종 방문지 수를 분리하고 필요한 식사·카페 후보를 보존했습니다. 실제 후보로 6·8시간 계획 생성 후 배포 API로 재검증했습니다.
- 실측 도시 간 경로 응답이 없는 사례에서는 `accessTrip.segment`를 비워 두고 카카오맵 외부 확인 링크를 제공합니다. 시간을 지어내거나 자동차 시간을 도보·대중교통 시간으로 사용하지 않습니다.

## 개인정보·인증·비용 경계

현재 단말 위치는 UI 전용 비직렬화 객체로만 사용하고 화면 종료/백그라운드에서 해제합니다. 위치 좌표·실제 거리 값은 테스트 로그와 캡처로 수집하지 않습니다. 서버 검색 스키마는 위치 중심 좌표를 거부하며 카카오 검색에는 사용자가 입력한 검색어만 보냅니다. 사용자가 명시적으로 입력·선택한 출발 장소는 추천 요청에 포함되며, 이것은 자동 수집한 단말 현재 위치와 구분됩니다.

거리순은 서버에서 받은 검색 후보 안에서 정렬한 것입니다. 현재 위치를 서버로 보내지 않으므로 전국 모든 장소에서 카카오맵과 완전히 동일한 인근 검색을 보장할 수 없습니다. 위치 제공자가 결과를 주지 않는 경우 정확도순으로 계속 검색할 수 있습니다. Android의 [통합 위치 제공자·단발 위치 요청](https://developer.android.com/reference/android/location/LocationManager)을 사용하며 앱 서버나 지도 API로 현재 좌표를 전송하는 구현은 없습니다.

Supabase 게이트웨이 `verify_jwt=false`는 이전 배포부터의 설정입니다. 자체 사용자 JWT와 비공개 입장 게이트를 그대로 유지했습니다. 공식 관리 API로 기존 version 25의 설정을 확인하고 무인증 보호 요청 403을 확인한 뒤 코드만 갱신했습니다. 인증 정책을 새로 완화하지 않았습니다.

앱 자체 카카오 한도 **300회/일** 유지, 카운터 초기화·유료 API 활성화 없음. 마지막 검색 검사 후 **299/300회**를 읽기 전용으로 확인했습니다. 이 한도는 새 코스 요청 횟수가 아니라 개별 공급자 요청 수이므로 남은 1회만으로 새 코스 전체를 검증하지 못할 수 있습니다. 추가 실호출 검사는 중단했습니다.
