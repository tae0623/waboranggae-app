## 원인

사용자가 알려준 광주 출발 주소 → 나주, 8시간 조건을 재현했습니다. 별도 출발 시각이 없어서 10:00~18:00, 보통 강도·자연/식사/카페·자동 식사·버스를 사용했습니다. 개인 출발 주소와 좌표는 이 문서 및 저장된 검사 결과에 넣지 않았습니다.

- **출발지에서 첫 장소까지의 도시 간 이동은 원래 총시간에 포함됐습니다. 귀가 이동은 포함하지 않습니다.**
- 재현된 실패는 총 480분으로 8시간 이내였지만 점심 도착이 14:48로 늦어진 사례였습니다.
- 초기 후보를 만들 때의 첫 이동 가정과 이후 좌표 기반 이동 시간이 달랐고, 초기 순위 계산에서 식사 시각을 다시 검증하지 않았습니다.
- 실제 길찾기 후 식사 조건 실패도 앱에서 일괄적으로 ‘여행 조건 초과’로 표시하고 지도 버튼까지 비활성화했습니다.

## 수정

1. 최초 추천·편집·실제 길찾기 갱신 모두 이동 반영 후 일정과 식사 조건을 다시 검증합니다.
2. 점심이 늦어지면 앞 장소의 여유 체류 시간을 최소 체류 기준 안에서 줄이고, 필요할 때 식사와 바로 다음 카페를 함께 앞당깁니다. 장소를 임의로 삭제하지 않습니다. 자동 조정 사실을 상세 화면에 표시합니다.
3. 재배치 비교는 서버 내부에서 최대 12개 후보로 제한합니다. 실제 길찾기는 선택된 재배치 1개 중 아직 조회하지 않은 구간만 추가 요청합니다.
4. 출발지→첫 장소, 장소 사이 이동, 체류, 대기·휴식, 총시간을 분리했습니다. 첫 식사 전 대기도 총시간·점수에서 빠지지 않습니다.
5. 충족하지 못한 조건을 구체적으로 표시하고 **동선 미리보기** 및 **시간·조건 변경**을 제공합니다. 조건 미충족 코스 저장은 계속 차단합니다.
6. 출발지를 2글자 이상 입력하고 450ms 멈추면 장소·주소 후보를 자동 조회합니다. 중복 조회 캐시, 이전 요청 취소 및 오래된 응답 무시를 적용했습니다. 후보를 직접 선택하면 좌표를 확정합니다.
7. 선택한 다른 도시의 주소를 여행 도시의 역·터미널 이름으로 바꾸지 않도록 했습니다.

자동완성은 기존 서버의 카카오 로컬 장소·주소 검색 연결을 사용합니다. 추가 키 입력은 필요 없습니다. 카카오맵 앱 자체의 검색어 추천 알고리즘을 복제한 것은 아닙니다. [카카오 로컬 API 문서](https://developers.kakao.com/docs/ko/local/dev-guide)
